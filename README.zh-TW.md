# PartGuard：小型工廠的離線視覺品檢系統

[English](README.md) | 繁體中文

PartGuard 是一套針對小型工廠設計的**離線視覺品檢原型**，主要用於墊片、螺帽、沖壓環等小型金屬零件的出貨前檢查。

系統可直接在本地端裝置執行，不需要將影像上傳至雲端。對每個偵測到的零件，PartGuard 會判斷其是否合格，並在不合格時提供對應的瑕疵原因。

目前系統使用 OpenCV 與 NumPy 實作，可直接在一般筆電 CPU 上執行，作為 ASUS UGen AI League（Battlefield Lightning）的概念驗證原型。

> **目前驗證範圍**
>
> 本專案現階段的金屬零件測試結果皆來自**程式產生的合成影像**，並非真實工廠拍攝的金屬零件。
> 真實環境中的金屬反光、油污、加工紋理與表面刮痕可能影響偵測結果，因此實際部署前仍需要使用真實零件重新校正與驗證。

---

## 支援的檢查項目

| 檢查項目 | 判斷內容 | 原因代碼 |
|---|---|---|
| 外徑尺寸 | 與同批零件的中位數比較，或依工程圖公差判定 | `SIZE_SMALL`, `SIZE_LARGE` |
| 外形完整性 | 檢查缺角、毛邊或明顯變形 | `DEFORMED` |
| 孔洞 | 檢查缺孔、孔徑異常與孔位偏心 | `HOLE_MISSING`, `HOLE_SIZE`, `HOLE_OFFCENTER` |
| 表面鏽蝕 | 依顏色判斷橘褐色鏽斑 | `RUST` |
| 表面刮痕 | 偵測零件表面的細長暗色線條 | `SCRATCH` |

尺寸判定支援兩種模式：

- 若已設定 `px_per_mm` 與工程圖允許的尺寸範圍，則直接依實際尺寸判斷。
- 若尚未進行實際尺寸校正，則以同一批零件的外徑中位數作為基準，比較各零件的相對差異。

## 系統架構

```text
 Camera + diffuse lighting + gray reference card
                        |
                        v
+------------------- Edge Device -------------------+
|                                                   |
|  1. Image preprocessing                          |
|     - gray-card lighting calibration              |
|     - foreground / part segmentation              |
|     - hole segmentation                           |
|                                                   |
|  2. Feature extraction                            |
|     - size                                        |
|     - roundness / solidity                        |
|     - hole size / position                        |
|     - rust / scratch features                     |
|                                                   |
|  3. Rule-based inspection                         |
|     - drawing tolerance / batch statistics        |
|     - PASS / FAIL                                 |
|     - defect reason codes                         |
|                                                   |
|  Stage II (planned):                              |
|     learned defect classifier on ASUS UGen300     |
+---------------------------------------------------+
              |                         |
              v                         v
     Annotated image / UI        Local JSONL log
```

目前金屬零件的檢查流程完全由 CPU 執行，包含影像前處理、特徵計算與規則式判定。

`partguard/backends.py` 中已保留 `HailoEmbedder` 介面，作為後續將學習式模型移植至 ASUS UGen300 / Hailo-10H 的擴充位置；**目前 UGen300 推論尚未實作。**

## 快速開始

### 1. 安裝套件

```bash
pip install -r requirements.txt
```

主要依賴：

```text
opencv-python
numpy
pyyaml
```

---

### 2. 產生合成測試資料

```bash
python tools/make_parts_synthetic.py
```

此程式會產生用於測試的合成墊片影像，包括正常零件以及不同種類的瑕疵。

這些圖片是由程式繪製產生，**不是真實金屬零件照片**。

---

### 3. 執行基本測試

```bash
python tests/test_smoke.py
```

測試內容包含：

- 正常零件應全部判定為合格
- 各種人工加入的瑕疵應被正確辨識
- 灰卡校正應能修正整體亮度下降造成的影響

---

### 4. 執行零件檢查

檢查合成測試圖片：

```bash
python run.py \
    --mode parts \
    --source samples/parts_batch_mixed.png \
    --lang zh
```

使用英文輸出：

```bash
python run.py \
    --mode parts \
    --source samples/parts_batch_mixed.png \
    --lang en
```

---

### 5. 使用攝影機即時檢查

```bash
python run.py \
    --mode parts \
    --source 0 \
    --show
```

按下 `q` 即可結束預覽。

## 輸出結果

每次檢查會產生三種結果。

### 終端機文字結果

例如：

```text
[parts_batch_mixed.png] FAIL

共 8 個，1 個合格、7 個需處理
- 第 2 個: 外形變形
- 第 3 個: 缺少孔洞
- 第 4 個: 尺寸偏大
- 第 5 個: 孔徑異常
...
```

可使用：

```bash
--lang zh
```

或

```bash
--lang en
```

切換中英文輸出。

### 標註後影像

判定結果會畫在原始圖片上，預設儲存於：

```text
out/
```

合格零件會以 `OK` 標示，不合格零件則會顯示對應的原因代碼。

### JSONL 檢查紀錄

每次檢查也會寫入：

```text
logs/inspections.jsonl
```

其中包含：

```json
{
  "ts": "2026-...",
  "mode": "parts",
  "source": "...",
  "passed": false,
  "latency_ms": 27.4,
  "details": [...]
}
```

因此可以保存每次檢查的結果、瑕疵資訊與推論延遲，方便後續追蹤與分析。

## 合成資料測試結果

可使用以下指令重新產生 benchmark：

```bash
python tools/benchmark_parts.py
```

測試會模擬：

- 不同整體亮度
- 不同顏色色偏
- 感測器雜訊
- 不同程度的人工瑕疵

預設使用固定 random seed `2026`，每種條件產生 100 批資料，每批包含 8 個合成零件。

在基準測試條件下，瑕疵強度設定為 `0.75`。

| 指標 | 結果 |
|---|---|
| 成功偵測不良零件 | 100%（95% CI：98.8–100%，共 330 個） |
| 正確指出瑕疵類型 | 100% |
| 良品誤判為不良 | 0%（95% CI：0–0.8%，共 470 個） |
| 每批 8 個零件的處理時間 | 中位數約 27 ms |
| 延遲 P95 | 約 68 ms |

以上延遲是在一般 CPU 上測量，**不代表 UGen300 的執行效能**。

## 不同瑕疵強度下的偵測能力

測試程式另外使用不同的 defect severity 模擬瑕疵由輕微到明顯的情況。

其中 `1.0` 代表非常明顯的人工瑕疵，此數值只是合成資料產生器所使用的相對尺度，不具有實際物理單位。

| 瑕疵強度 | 外形／尺寸 | 孔洞 | 表面瑕疵 |
|---|---:|---:|---:|
| 0.1 | 0% | 30%* | 0% |
| 0.25 | 0% | 32%* | 13% |
| 0.5 | 59% | 99% | 100% |
| 0.75 | 100% | 100% | 100% |
| 1.0 | 100% | 100% | 100% |

\* `HOLE_MISSING` 即使在低 severity 下仍可偵測，因此使孔洞類別在低強度時仍有約 30% 的偵測率；孔徑異常與孔位偏心則需要較明顯的差異才能穩定辨識。

這也反映目前規則式方法的限制：門檻設定得越嚴格，雖然能偵測更輕微的異常，但同時也更容易將真實產品的正常差異誤判為瑕疵。

## 光照與灰卡校正

金屬零件的視覺特徵容易受到環境光線影響，因此 PartGuard 支援使用固定在畫面中的**中性灰卡（gray reference card）**進行簡單的色彩與亮度校正。

灰卡位置設定於：

```yaml
configs/parts.yaml
```

例如：

```yaml
calibration:
  card_roi: [0.88, 0.86, 0.08, 0.08]
  target_gray: 128
```

程式會計算灰卡區域在 B、G、R 三個通道的平均值，再分別調整各通道增益，使灰卡在不同影像中維持接近相同的灰階值。

合成測試中，未使用灰卡校正時，當整體亮度降低到約 `0.7x` 以下，正常零件可能全部被誤判。

加入灰卡校正後，在約 `0.6x ~ 1.4x` 的亮度變化，以及約 ±20% 的模擬色偏範圍內，測試中的良品皆未出現誤報。

如果實際環境**沒有使用灰卡**，請從設定檔移除：

```yaml
calibration:
```

區塊，避免程式將其他影像區域誤認為灰卡。

需要注意的是，灰卡校正無法恢復已經過曝的影像。如果亮部像素已飽和為 255，原始資訊便已遺失，因此實際拍攝時仍應避免曝光過高。

## 感測器雜訊

測試中也加入不同程度的人工影像雜訊。

目前設定在約 `5 / 255` 的雜訊強度下仍能穩定運作；當雜訊提高至約 `10 / 255` 時開始出現誤報，在更高雜訊下判定結果會逐漸失效。

刮痕偵測會先估計零件表面的影像雜訊，並依雜訊程度動態提高判定門檻，避免將影像噪聲直接判定成刮痕。

代價是當影像本身非常吵雜時，較細微的真實刮痕也可能無法被偵測。

## 套用到真實零件

若要將目前的原型套用到真實生產環境，建議先完成以下校正流程：

1. **固定相機、治具與光源**

   相機位置與零件位置應盡量固定，並使用均勻的漫射光降低金屬反光。

   對高反射金屬，也可以進一步測試偏光片是否能改善眩光問題。

2. **收集良品資料**

   建議先拍攝至少 50 個實際良品，確認正常製程下尺寸、外形與表面特徵本身的自然變異。

3. **建立實際尺寸比例**

   使用已知尺寸的零件量測：

   ```yaml
   px_per_mm
   ```

   接著即可在 `configs/parts.yaml` 中設定工程圖的尺寸上下限：

   ```yaml
   size:
     min_mm: ...
     max_mm: ...
   ```

4. **重新調整判定門檻**

   目前設定值是依照合成資料調整，實際使用時應根據真實良品的分布重新設定：

   ```yaml
   shape:
   hole:
   surface:
   ```

   等相關參數。

5. **使用真實不良品驗證**

   最後需要蒐集實際製程產生的不良品，確認系統是否能辨識真正需要攔截的瑕疵。

## ROI 損益平衡模型

專案提供一個簡單的 ROI 試算工具：

```bash
python tools/roi_model.py
```

它用來估算：

> 一套自動品檢系統每年需要攔截多少批原本會流到客戶端的不良品，才能抵銷系統本身的成本？

例如，在以下**假設條件**：

```text
系統年成本：40,000
每批客退損失：20,000
系統可攔截比例：80%
```

損益平衡點約為：

```text
2.5 批 / 年
```

也就是平均每年只要能避免約 2.5 批原本會流到客戶端的不良品，在此假設下即可抵銷系統成本。

這些數字只是展示計算方式，**並非真實工廠成本資料**。實際評估時必須替換成有依據的設備、人工、報廢與客退成本。

## 目前限制與後續方向

目前 PartGuard 仍屬於概念驗證階段，使用時需要注意以下限制：

- **目前的金屬零件量化結果全部來自合成影像。** 真實金屬表面的反光、油污、加工紋理與細微毛邊尚未經過實際資料驗證。
- **目前主要採用規則式判定。** 對非常細微的瑕疵可能無法穩定辨識，偵測能力會受到門檻設定影響。
- **UGen300 整合尚未完成。** `HailoEmbedder` 目前只是預留介面，尚未實作 Hailo-10H 上的實際模型推論。
- **目前延遲數據是在一般 CPU 上量測。** 因此不能用來代表 UGen300 上的最終效能。
- **公開工業瑕疵資料集的授權需要個別確認。** 部分資料集僅允許研究或非商業用途，可能與競賽或未來商業部署的需求不符。本 repository 不包含任何第三方資料集影像。

後續預計加入真實工廠零件資料，並評估將學習式瑕疵分類模型部署至 ASUS UGen300，以提升對細微、複雜表面缺陷的辨識能力。
